The landing page for Diluvium: what the language adds, a working interpreter
in the page, and the way in to everything else.

## What is here

```
public/index.html   the page
public/start.sh     the installer, served at /start
src/app.js          wiring
src/repl/           WASI shim, runtime loader, line editor
src/release.js      reading the release mirror
src/prism-diluvium.js   Lua highlighting, extended for Diluvium
test/smoke.mjs      drives the real page in a real browser
```

## The interpreter is real

The panel is not a transcript or a simulation. The page fetches
`libdiluvium_wasi.wasm` from the release mirror and drives it through
`repl_eval` — the same entry point the native REPL uses, so continuation
prompts, expression echo and tab completion all come from the runtime rather
than from a guess made in JavaScript.

`doc/repl-reference.html` in the [diluvium
tree](https://github.com/Aloecraft-org/diluvium) is the authoritative
description of that contract, and `src/repl/` is adapted from it. When the
runtime's exports or imports change, that file changes first.

Three things about the build are not guessable from outside:

- It must be `libdiluvium_wasi.wasm`. `diluvium_wasi.wasm` is a command module
  whose `_start` runs the interpreter against stdin, and
  `diluvium_compiler_wasi.wasm` is `luac`.
- Call `__wasm_call_ctors()` first. The module exports that rather than
  `_initialize`, so it is not a WASI reactor and nothing sets up libc for you.
- Drive it with `repl_eval`, not `run_lua`. `run_lua` cannot distinguish
  unfinished input from broken input, and `1 + 1` prints nothing.

## The release mirror

Nothing here vendors a runtime. `/release` is generated by
`util/scripts/release_mirror.py` in launchkit from `changelog.json` in the
diluvium tree, and the page reads `/release/releases.json` for the version
badge and the download links. `/release/latest/` is a symlink the mirror
maintains, so the kernel URL never needs updating when a release is cut.

In production the mirror is same-origin. For development against the deployed
one:

```sh
RELEASE_BASE=https://diluvium.aloecraft.org/release npm start
```

`/release/` sends `Access-Control-Allow-Origin: *`, so that works from
localhost.

## Development

```sh
npm install
npm run build          # -> dist/
npm start              # dev server on :8081
npm run stage-mirror   # copy the real kernel into dist/release/
npm test               # build, serve, drive the REPL in Chromium
```

`npm test` needs `dist/` built and a staged mirror; it asserts on things that
have actually broken — doubled output, continuation prompts failing to open,
an error killing the session — and writes a screenshot to `test/.out/`.

To test against what is deployed rather than a local build:

```sh
SITE=https://diluvium.aloecraft.org npm test
```

## Deployment

Built by launchkit and rsynced to `/var/www/html/diluvium/` on cloud1,
alongside `release/` (the mirror) and `lab/` (diluvium-lab). The site is
static; there is no server-side anything.
