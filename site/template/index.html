Small language. Sealed runtime. Runs anywhere.

Diluvium is a general-purpose language and the runtime underneath it. Modern syntax — string interpolation, switch, defer, safe navigation — compiled to one portable bytecode that behaves the same in a browser tab, on a server, or on hardware with a few hundred kilobytes to spare. The whole runtime is under a megabyte, and a program can reach nothing you did not hand it.

The syntax is a compatible superset of Lua 5.5, so existing Lua code runs unmodified. If you have never written Lua, there is nothing to catch up on.

curl -fsSL https://diluvium.aloecraft.org/start | sh

The language

Small, plain, and readable on sight. Everything below compiles straight to bytecode and none of it takes a reserved word, so existing code keeps working and adoption is as gradual as you want it.

String interpolation

local name = "world"
local pi = 3.14159

print($"Hello, {name}!")

-- pi is 3.14
print($"pi is {pi::%.2f}")
-- [   42]
print($"[{42::%5d}]")

Everything after :: goes to string.format. It is :: and not : because : already means a method call.

Null coalescing & safe navigation

local cfg = user_cfg ?? defaults

local city = user?.address?.city
local port = cfg?.server?.port ?? 8080

-- not called when nil
handler?.on_event(payload)

-- assign only if nil
port ??= 8080

Once a value is nil the rest of the chain is skipped entirely. It tests nil, not falsiness, so false?.x still raises.

switch

switch code do
    case 200, 201, 204 then
        print("ok")
    case 301, 302 then
        print("redirected")
    default
        print($"odd: {code}")
end

The subject is evaluated once, a case can list several values, and there is no fallthrough. A contextual keyword, so local switch = 1 still works.

defer & with

local f = io.open("data.txt")
defer f:close()   -- however we exit

with g = assert(io.open("o.txt")) do
    g:write("done")
end               -- closed, always

Both desugar to Lua's to-be-closed variables, so unwinding is inherited rather than invented: they run on break, goto, return, an error, and coroutine.close.

Compound assignment

total += 10    -- -= *= /= //= %= ^=
name  ..= "uvium"
flags |= 0x04  -- &= <<= >>=
port  ??= 8080

The target's prefix is evaluated once, so t[next_key()] += 1 calls next_key a single time. There is no ~= form — that already means "not equal".

Secure functions

~function check()
    local key = "not-in-the-clear"
    return $"key is {key}"
end

Names and string constants are scrambled at rest, so strings on the bytecode does not turn them up. Cryptographically weak — obfuscation, not protection.

The core

The syntax is the part you see. Underneath it is a machine built to be small, portable, and sealed — the one running in the panel above, and the one DRT embeds.

One bytecode, every target

Source compiles to a single portable bytecode with one set of semantics behind it. The same file runs under WebAssembly in this page, on x86_64 and ARM64 natively, and on hardware smaller than either. Natively it is one static binary under a megabyte, with nothing to install alongside it.

Sealed by default

A program starts with no ambient authority. It cannot open a socket, read a file, or reach the process it lives in, because there is nothing in the runtime to call. Everything it can touch is handed in from outside, nothing can pass on more than it was given, and the trusted base enforcing that is small enough to read end to end.

Freeze and resume

A running program can be snapshotted mid-execution into a flat string of bytes and brought back later at the exact instruction it left — in another process, or on another machine. A program does not have to be running to exist.

DRT — the Diluvium RunTime

Diluvium is purely the language. DRT is everything around a running program: the swarm, a transparent host with root config, hostcall connectors, orchestration, transport, observability, and a REPL. The two are concentric, not parallel — DRT embeds the language core, so there is never a second runtime with different behaviour for the same program, and installing DRT gets you everything.

One binary, three verbs

drt run prog.dlua                 # one program, to completion
drt repl                          # a REPL, which is an instance
drt --config app.host.lua start   # a deployment: swarm, listeners, relay

A static binary with no runtime dependencies, and a tunnel verb that carries ssh to anything from anywhere through the relay. drt start reads a diluvium-host config unchanged, so a deployment moves to DRT by swapping the binary and editing no files.

A config grants; a program names

print(host.time())         -- the clock costs a grant
host.fs.read("note.txt")   -- inside the granted directory
host.call("sql/exec", {sql = "..."})

A deployment is a config plus a program. The config names the ceiling and wires each connector to a place; the program names resources inside those places, through the host library. An ill-scoped grant fails at startup, by name — never as a mystifying denied at first call.

Two profiles, and the facts travel with the bytes

Every release ships full — the connectors, listeners, the relay and tunnel — and slim, the distribution-size profile. Which connectors each carries, which diluvium revision is inside and which dv ABI it speaks are recorded in BUILDINFO.txt beside the binaries, and drt buildinfo reads the same facts back off the binary itself. DRT versions independently of Diluvium; the coupling is recorded, not encoded.

The current list is in BUILDINFO.txt on the mirror.

dollup — programs, installed

dollup installs Diluvium programs and the capabilities they run on, and moves hibernated instances between machines. It fetches programs into an app — one directory holding the code, the sources it came from, and a lockfile pinning every version and hash — so the same app rebuilds byte for byte anywhere. A DRT app is a config plus a program; dollup brings the program half and never writes the config.

Nothing executes during an install

A manifest is data, so there is no setup script to audit. Packages are named by the hash of their contents and listed in an index the publisher signs, which is what lets a mirror, a git remote and an offline copy be the same artifact rather than three you have to trust separately.

Installing never grants

What a program may do lives in your config, not in the package. And DRT never fetches, so the trust boundary is the directory dollup writes rather than dollup itself.

An app is a directory

dollup init                # start an app here
$EDITOR dollup.json        # add a source; pin its key
dollup add telemetry@^1    # fetch, hash-check, lock, populate code/
dollup get drt             # the runtime, hash-checked, dropped beside it

Pre-release: the format is settling and the standard package repo is not published yet. When it is, its signing key appears on dollup's page, and you pin it in a file you own.

Install

Three things, and you may want only the first. Each is a single static binary with no runtime dependencies, verified against the checksums its release published.

The language — diluvium, the interpreter

curl -fsSL https://diluvium.aloecraft.org/start | sh

Detects your platform, downloads from the mirror, and verifies the binary against the SHA256SUMS.txt the release workflow published. Installs to /usr/local/bin, or ~/.local/bin when that is not writable.

Read it before you pipe it to a shell

Sensible. It is a single POSIX sh script with no dependencies beyond curl or wget:

curl -fsSL https://diluvium.aloecraft.org/start | less

Options: --prefix DIR, --version TAG, --compiler to also install the bytecode compiler.

Direct download

Single static binary, no runtime dependencies.

    The runtime — drt, which embeds the language

    curl -fsSL https://software.aloecraft.org/releases/diluvium-drt/latest/install.sh | sh

    Same shape: platform detection, a download from the DRT mirror, a check against SHA256SUMS.txt, and drt buildinfo printed at the end so you can see which diluvium revision is inside. DRT_SLIM=1 takes the size profile; DRT_VERSION=vX.Y.Z pins a release. Linux x86-64 and macOS today; Linux ARM64 and Windows are not built yet.

    Direct download

    The full profile; slim is the same name with drt_slim_.

      The programs — dollup, which installs them

      curl -fsSL https://github.com/Aloecraft-org/dollup/releases/latest/download/install.sh | sh

      Every release carries SHA256SUMS.txt and a BUILDINFO.txt naming the commit it was built from. DOLLUP_VERSION=vX.Y.Z pins a release, DOLLUP_PREFIX= chooses the directory. Or skip the install entirely: dollup get drt is how an app fetches the runtime, and needs no config at all.
